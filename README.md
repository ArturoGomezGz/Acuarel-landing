## 2. Análisis del sitio actual

**Estructura:** 4 páginas — `/` (Home + Productos + Contacto en footer), `/nosotros`, `/clientes`, `/galera` (galería).

**Plataforma:** Wix (assets alojados en `static.wixstatic.com`).

### Problemas detectados

| # | Problema | Impacto |
|---|---|---|
| 1 | Sin CTA claro: no hay formulario, ni WhatsApp, ni "solicita cotización" | Se pierden leads |
| 2 | Sin email de contacto visible | Fricción para contactar |
| 3 | Sin redes sociales enlazadas (la de Facebook existe pero está huérfana) | Nula prueba social |
| 4 | Diseño anticuado, poco responsive, tipografía de plantilla genérica | Baja credibilidad |
| 5 | Textos con faltas de ortografía y acentos ("dandole", "tapatia", "Ayuntamiendo") | Baja credibilidad |
| 6 | «Después de 30 años» — texto congelado desde ~2010 | Desactualizado |
| 7 | Imágenes sin optimizar y sin `alt` descriptivo | Rendimiento y SEO |
| 8 | Sin metadatos SEO ni datos estructurados de negocio local | Invisible en búsquedas locales |
| 9 | El diferenciador NSPI está escondido en la página de clientes | Se desaprovecha |
| 10 | Sin mapa ni ubicación embebida | Fricción para visitar |

### Oportunidades para la nueva landing

- Hero con propuesta de valor + CTA doble (WhatsApp / cotización).
- Barra de credibilidad: *+45 años · Cobertura nacional · Norma NSPI · +35 proyectos*.
- Servicios agrupados en 3 bloques legibles — **Construcción** · **Equipamiento** · **Mantenimiento** — en lugar de una lista plana de 16 puntos.
- Galería de proyectos con las fotos reales ya rescatadas.
- Muro de logotipos de clientes.
- Formulario de contacto + WhatsApp flotante + mapa.
- SEO local (`LocalBusiness` schema, meta tags, sitemap).

## 6. Stack técnico

**Astro 7 + Tailwind CSS 4**, sitio 100% estático.

Astro corre sobre Vite (misma velocidad de desarrollo), pero en lugar de una SPA genera HTML
plano y envía **0 KB de JavaScript de framework** al navegador. Para una empresa que vive de
búsquedas locales, el SEO y el tiempo de carga son parte del producto. El poco JS que hay
(menú móvil, filtros de galería, visor de imágenes, revelado al hacer scroll) va inline y
suma unos pocos KB.

### Estructura

```
landing/
├── src/
│   ├── assets/            imágenes optimizadas en build (WebP/AVIF + srcset)
│   │   ├── clientes/      5 logotipos
│   │   └── proyectos/     18 fotografías curadas de la galería original
│   ├── components/        Header, Hero, Credibilidad, Servicios, Proyectos,
│   │                      Nosotros, Clientes, Contacto, Footer, BotonWhatsapp,
│   │                      TituloSeccion, Icono
│   ├── data/              site.ts, servicios.ts, proyectos.ts, clientes.ts
│   ├── layouts/Layout.astro     meta tags, Open Graph y schema LocalBusiness
│   ├── pages/             index.astro, aviso-de-privacidad.astro
│   └── styles/global.css  paleta y tipografía (tokens de Tailwind 4)
├── public/                favicon.svg, robots.txt
└── .env.example
```

**Todo el contenido editable vive en `src/data/`.** Cambiar un teléfono, agregar un cliente o
sumar una foto no requiere tocar componentes.

### Comandos

```bash
cd landing
npm install
npm run dev        # servidor de desarrollo
npm run build      # genera dist/ listo para publicar
npm run preview    # revisa el build localmente
```

### Secciones de la landing

Hero · Barra de credibilidad · Servicios (3 bloques) · Galería de proyectos con filtros y
visor · Nosotros · Muro de clientes + lista completa · Contacto (WhatsApp, teléfonos, mapa y
formulario) · Footer · Botón flotante de WhatsApp.

### Decisiones tomadas

| Tema | Decisión |
|---|---|
| Años de experiencia | Se calcula desde 1980 en tiempo de build; nunca vuelve a quedar congelado |
| Formulario | Sin backend: apunta a un servicio tipo Formspree vía `PUBLIC_FORM_ENDPOINT`. Mientras no exista, se muestra deshabilitado con aviso y el CTA de WhatsApp cubre el hueco |
| 16 servicios | Reagrupados en Construcción / Equipamiento / Mantenimiento |
| Ortografía | Todos los textos del sitio original fueron corregidos |
| NSPI | Movido al hero y a Nosotros: es el diferenciador más fuerte y estaba escondido |
| Accesibilidad | Enlace "saltar al contenido", `alt` descriptivo en cada foto, foco visible, navegación por teclado en el visor, respeto a `prefers-reduced-motion` |
| Imágenes | Astro genera WebP con `srcset` por breakpoint; el build baja las 18 fotos de ~7 MB a lo necesario por viewport |

### Publicación

`npm run build` produce `dist/`, que se sube tal cual a Netlify, Vercel, Cloudflare Pages o
cualquier hosting estático. Antes de apuntar el dominio hay que resolver los pendientes de la
sección 5 y definir `PUBLIC_FORM_ENDPOINT`.
